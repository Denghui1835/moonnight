## 1. 本轮修复的两处风险

### 1.1 摄像头降级泄漏

`startGame("camera")` 中，`getUserMedia` 成功但 MediaPipe 模型加载失败时，原来的 `catch` 只切换了模式，没有关闭已打开的摄像头流。

修复（`src/main.ts`）：

```ts
} catch {
  tracker.stop();       // 显式停止轨道，避免摄像头指示灯常亮
  tracker = null;
  mode = "keys";
  video.classList.add("hidden");
  toast("摄像头打不开，已切到键盘模式");
}
```

验证（`qa.mjs` → camera leak run，网络层屏蔽 `*/wasm/*` 与 `*/models/*`）：

| 检查 | 结果 |
|---|---|
| 自动降级到键盘模式并提示 | PASS |
| 轨道真实关闭：`trackStates: ["ended"]`，`srcObject: null` | PASS |
| 两个开始按钮恢复可点 | PASS |
| 降级过程无页面报错 | PASS |

### 1.2 音频时钟单点故障

原来 beat 只从 `AudioContext.currentTime` 推。标签页被挂起、音频上下文暂停时，节拍会停或跳。

修复（`src/audio.ts` 的 `syncBeat()`）：

- `AudioContext.currentTime` 为主时钟；
- 检测到主时钟不前进时，用单调递增的墙钟增量兜底；
- 上下文恢复时重新锚定 `beatOrigin`，不补跳、不回退。

验证：

| 检查 | 数值 |
|---|---|
| 上下文挂起 1024ms，beat 仍前进 | `6.55 → 7.93 → 8.71`，期望增量 1.39，PASS |
| 恢复后 beat 不跳变 | 实测增量 `0.78`，期望 `0.64`，PASS |
| 音频初始化失败不会禁用开始按钮 | 代码路径 + 降级测试，PASS |

### 已修复：舞蹈板点不动

第一轮真机事件测试中，按钮高亮与判定全部失败，但合成 `PointerEvent` 能让游戏继续——说明监听器没问题，是命中测试失败。

原因：`#hud` 是 `pointer-events: none`（HUD 不挡画布），该属性会被子元素继承；`.touchpad` 没有显式恢复 `pointer-events`，于是触点直接穿过按钮落到画布上。

修复（`src/style.css`）：

```css
.touchpad {
  pointer-events: auto;
}
```

复测：真实 `touchStart` 即触发 `pointerdown`，按钮高亮、判定、计分全部通过。截图：`20-phone-title` / `21-phone-tutorial` / `22-phone-level`。

## 6. 已知限制

- **假摄像头没有人**：摄像头流程只验证了「模型加载、轨道、无人体时的宽松判定」，真实骨骼识别需要真人复测。
- **CDP 按键不是受信任输入**：部分判定用页面内 `pushKey` 驱动；另有一条真实 `Input.dispatchKeyEvent` 用例覆盖真实键路径。
- **触控是模拟手机**：21 项通过 CDP 设备模拟 + 真实 `dispatchTouchEvent`，未在实体手机上跑；`pointerdown/up` 路径与真机一致，但 Safari / iOS 仍需一次人工复测。
- **3D 帧率只在桌面测过**：桌面 Edge 60fps 稳定；手机竖屏按 1.5 倍像素比渲染并缩小人物，未在低端安卓机上实测帧率。
- **WAV 体积**：11.6 MB，仓库可接受；演示优先用 1.6 MB 的 `moonnight-metal.mp3`。
- **摄像头测试偶发挂起**：headless 下摄像头 target 偶发整页冻结，导致一次轨道检查超时；重跑通过（37/37），未改动游戏代码。

### 一个踩过的坑：镜像有两个域名，分属两套发布凭证

`moonnight-c1n29gwia6s.qoder.zone` 与 `moonnight-mirror-rvzkngbzcr9.qoder.website` 都能打开，但它们是两个独立站点：本会话的 Qoder Sites 凭证 `list_sites` 只返回 **zone** 这个项目（`月夜 MoonNight（国内镜像）`，`site_id 01a16c76-5484-7253-8d6b-bcce69af0a65`，access public），对它执行 `prepare_site` + `publish_site` 生效；**website** 那份要另一套凭证才管得了，从这里 `get_site` 报 `sites_request_failed`。

教训：只发一个域名，另一个就会停在旧包。本轮先把 zone 发到 `index-DKMki3oD.js`，随后 website 也补齐，**2026-10-24 15:50 三个入口实测一致**：

|---|---|
| GitHub Pages | `index-DKMki3oD.js` + `index-D_LXfvHZ.css` |

## 9. 3D 渲染层验收（2026-10-24）

### 结构

## 13. 手机上「该按哪个键」的高亮，以及一条空过的检查（2026-10-24）

教学关第一次上手最容易卡的地方不是看不懂动作，而是**动作名和舞蹈板子标签对不上**：`↑` 那个键底下写着「张开」，可 cue 让她跳的是「举高」「双手抓」「手伸直」——四个动作共用同一个方向键，玩家得先在心里把「举高」翻译成「↑」再翻译成底下那个写着「张开」的按钮。桌面上有实体键盘可以对，手机上没有。

所以 cue 出现时把对应那颗舞蹈键点亮（`src/main.ts` 的 `syncHud` 里按 `cache.padKey` 变化时切换 `.cue` 类，样式在 `src/style.css` 的 `(hover:none)` 段里：描边加亮 + 一点月光辉光，箭头和子标签同时提亮）。用类切换而不是改按钮文案：文案是四个方向的固定名字，改了反而每次 cue 都在跳字。

| 检查 | 实测 |
|---|---|
| `the cue key lights up exactly one pad button`（新增，逐帧轮询） | `{"ok":true,"key":"→","lit":"→"}` |

顺带修了一条一直在**空过**的检查。`pad does not overlap move cue` 原来是 `noOverlap(pad, cue) || cue.w === 0`——教学关刚进场时动作名还是空串，`.cue` 是个由子内容撑宽的 flex，于是塌成 `{"x":187.5,"y":622,"w":0,"h":0}`，第二个条件直接为真，重叠根本没被测。现在先 `waitFor(__game.hud.moveName !== '')` 再量：

```
PASS  pad does not overlap move cue  {"pad":{"x":50,"y":740,"w":275,"h":58},"cue":{"x":140.8,"y":592,"w":93.4,"h":30},"name":"张开"}
```

教训记一条：**几何断言要么确认量到的是非零盒子，要么就会退化成永真**。后面再加水印安全区之类的检查，都按这个补一次「元素此刻真的有尺寸」的前置。

## 15. 「跳对」里那 4 个教学的两种说法（2026-10-24 深夜）

结算页的数字一直是 `stats.hits`，里面混着教学关的 4 次跟读。上一轮加的标签规则是 `hits > tutorialHits ? "跳对 · 含教学" : "跳对"`，漏了一种情况：**跳完教学、第 1 关第一个动作就按错死掉**，此时 `hits === tutorialHits === 4`，屏幕上显示「跳对 4」却没有任何说明——玩家会以为自己跳了 4 个正式动作，看着像计数 bug。

现在按关系分三支（`src/main.ts` 的 `hitsLabel`）：教学计数为 0 → 「跳对」；`hits > tutorialHits` → 「跳对 · 含教学」；`hits === tutorialHits > 0` → 「跳对 · 全是教学」。

两支都要有确定的覆盖，不能靠一条跟着实现写的断言：

| 运行 | 死法 | 实测 |
|---|---|---|
| `keyboardRun`（自动点按打到 clearInterval） | 关里已经跳对过 | `{"hits":"7","tutorialHits":4,"hitsLabel":"跳对 · 含教学"}` |
| 新增 `allTutorialDeathRun` | 教学一跳完、进关第一个动作就按错 | `{"hits":"4","tut":4,"lbl":"跳对 · 全是教学","level":"第 1 关","heads":"3 人"}` |
| `mobileRun`（触控） | 关里跳对 1 个后错死 | `{"hits":"5","tutorialHits":4,"hitsLabel":"跳对 · 含教学"}` |

新那条 run 的关键是**进关后立刻停手**：教学阶段专用的 `__tutOnly` 定时器只认 `phase === 'tutorial' && hud.subtitle === '跟着做。'`，`waitFor(phase === 'level')` 一返回就 `clearInterval`，所以 `hits` 恰好等于教学计数；复用原来那个连关里也打的 `AUTO` 会多跳对几个，`hits === 4` 就不可复现了。桌面主运行那条改成断言「标签与数字说的是同一个故事」，具体分支字符串交给新 run 钉死。

回归：桌面 **47/47**、触控 **29/29**（`tools/.out/qa-m.log`、`tools/.out/touch-m.log`），新产物 `index-CaSHR2cu.js` 763.64 kB（gzip 204.66 kB）、`index-DlElkWp7.css` 8.62 kB（gzip 2.66 kB）。截图新增 `11-death-all-tutorial`。

### 16.4 顺带修掉的一个静默 404

每轮 QA 的控制台都稳定出现 7 条 404：`/sfx/*`、`/music/*`、`/plates/*`。原因是这些路径被写成绝对地址。开发服务器 base 是 `/`，一切正常；部署到 GitHub Pages（base `/moonnight/`）后全部 404——而 `audio.ts` 对每个音效都有「缺文件就回退到程序合成」的兜底，于是**线上会静默丢掉真实音轨与采样，页面不报错、玩家只听见合成音**。

改法：`const SITE = import.meta.env.BASE_URL`，拼进 `SFX_FILES`、`MUSIC_FILE`（`audio.ts`）与 `PLATE_URL`（`render3d.ts`）。改后控制台 404 归零。这一条已写进规划书表 7（关键问题与解法）。
