## 1. 本轮修复的两处风险

### 1.1 摄像头降级泄漏

`startGame("camera")` 中，`getUserMedia` 成功但 MediaPipe 模型加载失败时，原来的 `catch` 只切换了模式，没有关闭已打开的摄像头流。

修复（`src/main.ts`）：

```ts
} catch {
  tracker.stop();       // 显式停止轨道，避免摄像头指示灯常亮
  tracker = null;
  mode = "keys";
  video.classList.add("hidden");
  toast("摄像头打不开，已切到键盘模式");
}
```

验证（`qa.mjs` → camera leak run，网络层屏蔽 `*/wasm/*` 与 `*/models/*`）：

| 检查 | 结果 |
|---|---|
| 自动降级到键盘模式并提示 | PASS |
| 轨道真实关闭：`trackStates: ["ended"]`，`srcObject: null` | PASS |
| 两个开始按钮恢复可点 | PASS |
| 降级过程无页面报错 | PASS |

### 1.2 音频时钟单点故障

原来 beat 只从 `AudioContext.currentTime` 推。标签页被挂起、音频上下文暂停时，节拍会停或跳。

修复（`src/audio.ts` 的 `syncBeat()`）：

- `AudioContext.currentTime` 为主时钟；
- 检测到主时钟不前进时，用单调递增的墙钟增量兜底；
- 上下文恢复时重新锚定 `beatOrigin`，不补跳、不回退。

验证：

| 检查 | 数值 |
|---|---|
| 上下文挂起 1024ms，beat 仍前进 | `6.55 → 7.93 → 8.71`，期望增量 1.39，PASS |
| 恢复后 beat 不跳变 | 实测增量 `0.78`，期望 `0.64`，PASS |
| 音频初始化失败不会禁用开始按钮 | 代码路径 + 降级测试，PASS |

### 已修复：舞蹈板点不动

第一轮真机事件测试中，按钮高亮与判定全部失败，但合成 `PointerEvent` 能让游戏继续——说明监听器没问题，是命中测试失败。

原因：`#hud` 是 `pointer-events: none`（HUD 不挡画布），该属性会被子元素继承；`.touchpad` 没有显式恢复 `pointer-events`，于是触点直接穿过按钮落到画布上。

修复（`src/style.css`）：

```css
.touchpad {
  pointer-events: auto;
}
```

复测：真实 `touchStart` 即触发 `pointerdown`，按钮高亮、判定、计分全部通过。截图：`20-phone-title` / `21-phone-tutorial` / `22-phone-level`。

### 同时补齐的两处触控细节

- **44px 触控目标**：结算页「再跳一次」实测只有 43px 高，触屏下 `.screen button, .tutorial-bar button { min-height: 44px; }`，复测按钮 `145×44`，教学栏按钮也升到 44px 且不与舞蹈板重叠。
- **隐藏态不再可点**：舞蹈板自查 `pointer-events: auto` 后，即使 `#hud` 透明仍可接收触点；补 `#hud.hidden .touchpad { pointer-events: none; }`，并用 `elementFromPoint` 断言标题页底部不会命中隐藏按钮。

## 6. 已知限制

- **假摄像头没有人**：摄像头流程只验证了「模型加载、轨道、无人体时的宽松判定」，真实骨骼识别需要真人复测。
- **CDP 按键不是受信任输入**：部分判定用页面内 `pushKey` 驱动；另有一条真实 `Input.dispatchKeyEvent` 用例覆盖真实键路径。
- **触控是模拟手机**：21 项通过 CDP 设备模拟 + 真实 `dispatchTouchEvent`，未在实体手机上跑；`pointerdown/up` 路径与真机一致，但 Safari / iOS 仍需一次人工复测。
- **3D 帧率只在桌面测过**：桌面 Edge 60fps 稳定；手机竖屏按 1.5 倍像素比渲染并缩小人物，未在低端安卓机上实测帧率。
- **WAV 体积**：11.6 MB，仓库可接受；演示优先用 1.6 MB 的 `moonnight-metal.mp3`。
- **摄像头测试偶发挂起**：headless 下摄像头 target 偶发整页冻结，导致一次轨道检查超时；重跑通过（37/37），未改动游戏代码。

## 9. 3D 渲染层验收（2026-10-24）

### 结构

- `src/render3d.ts`：Three.js r170 场景（人偶、镜面、房间、光、后期），实现 `SceneRenderer` 接口。
- `src/stage.ts`：原 Canvas 2D 场景保留为兜底，接口不变。
- `src/main.ts`：启动时探测 WebGL；探测失败直接走 2D，游戏逻辑与判定完全不依赖渲染器。

### 场景内容

| 元素 | 做法 |
|---|---|
| 镜面 | `Reflector` 整面后墙 + 内侧发光边框；反射纹理 512（窄屏）/1024 |
| 人偶 | 圆柱骨骼 + 关节球 + 球头 + 礼帽 + 裙摆；颜色全黑，靠轮廓光读形 |
| 轮廓光 | `MeshStandardMaterial.onBeforeCompile` 注入菲涅尔项；老师暖金、僵尸冷青 |
| 房间 | 程序化地板（roughness 0.52）、月光窗、树影、乌鸦、红绳、光柱、尘埃 |
| 后期 | RenderPass → UnrealBloom → 自定义调色（暗角/噪点/错位/血）→ OutputPass，ACES 色调映射 |
| 竖屏 | 相机拉到 8.8、人物整体 ×0.72、僵尸横向 ×1.14 并压到老师身后 |

### 10.2 托管方水印浮层与移动端安全区

Qoder Sites 会在页面右下角注入 `<qoder-sites-badge id="qoder-sites-watermark">`（`position:fixed`、`z-index:2147483647`、实测 `147×32`，位于 `x 218–365 / y 766–798`）。浮层由托管方注入，**不做删除**，只把可能被压住的内容抬开（`src/style.css`）：

```css
html:has(#qoder-sites-watermark) .touchpad      { bottom: calc(max(14px, env(safe-area-inset-bottom)) + 48px); }
html:has(#qoder-sites-watermark) #hud .bottom   { bottom: calc(max(14px, env(safe-area-inset-bottom)) + 126px); }
html:has(#qoder-sites-watermark) #hud.tutorial-on .bottom { bottom: calc(max(14px, env(safe-area-inset-bottom)) + 182px); }
html:has(#qoder-sites-watermark) #hud.tutorial-on .tutorial-bar { bottom: calc(max(14px, env(safe-area-inset-bottom)) + 126px); }
```

375×812（DPR 3）实测，浮层与可点区域的重叠面积：

| 元素 | 修复前 | 修复后 |
|---|---|---|
| 舞蹈板 `.touchpad` | 与浮层重叠 `3 424 px²`，`bottom:14px`（板顶 y 740、底 y 798） | 重叠 **0**，板底抬到 **y 750**（顶 y 692），完整避开 y 766 起的浮层 |
| 右起第一键 `button:nth-child(4)` | 重叠 `1 984 px²` | **0** |
| 教学栏 `#tutbar` | 会被压住 | **0**（抬到浮层上方 126px 起） |
| 动作提示 `#cue-key` | — | **0** |
| 结算页 / 终章页 / 桌面 1280×800 | — | **0**（浮层只压背景） |

`:has()` 只在浮层真实存在时生效，本地 `npm run dev`（无注入）仍是原来的 `bottom:14px`，不额外抬高。截图编号：`40-wm-mobile-title`、`41-wm-mobile-tutorial`（入库为 `docs/screenshots/11-wm-touchpad-clear.png`）、`42-wm-mobile-result`、`43-wm-mobile-ending`、`44-wm-desktop-result`。

线上镜像同样加了 2 项 DOM 断言（`QA_LIVE=1 npm run touchqa`）：`live: host badge covers no touch target`、`live: zero page errors`。

### 10.3 测试脚本自身的两处加固

| 现象 | 原因 | 处理 |
|---|---|---|
| 桌面套件在假摄像头一步崩溃：`ReferenceError: __game is not defined`（5 项摄像头检查未跑） | 软渲染 + 3D 冷启动时姿势模型加载超过 60 s，`waitFor` 超时后 `eval` 直接引用裸全局变量 | 全部改为 `window.__game` 守卫、启动等待放宽到 120 s、拔摄像头前先判 `srcObject` 是否存在；超时只会变成检查失败，不再让整轮崩掉 |
| 套件偶发在第 1 项挂住：`{"n":0,"vis":"hidden"}` | headless 新标签被后台节流，`rAF` 暂停 | 启动参数加 `--disable-backgrounding-occluded-windows`、`--disable-renderer-backgrounding`、`--disable-background-timer-throttling`，并调用 `Emulation.setFocusEmulationEnabled` + `Page.setWebLifecycleState("active")` |
| CDP 端口被另一个会话占用 → `EPERM tools/.out/profile-9333` | 两个会话同时跑 QA | `qa.mjs` 与 `touchqa.mjs` 都支持 `QA_PORT_OFFSET` |
